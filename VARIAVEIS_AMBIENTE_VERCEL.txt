==============================================
  VARIÁVEIS DE AMBIENTE PARA VERCEL
  Projeto: KFS Online (kfs_online)
  Atualizado: março 2026
==============================================

Notas:
- Auth principal: Supabase (ver .env.example e README). NEXTAUTH abaixo pode ser legado / opcional conforme o teu deploy.
- Webhook Stripe na app: /api/stripe/webhook (confirmar no código em app/api/stripe/webhook).
- Node na Vercel: 20.x (alinhado a package.json engines).

COPIE E COLE ESTAS VARIÁVEIS NA VERCEL:

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1) SUPABASE (Base de Dados + Auth)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

NEXT_PUBLIC_SUPABASE_URL=https://teu-project-ref.supabase.co

NEXT_PUBLIC_SUPABASE_ANON_KEY=
[Supabase → Settings → API → anon/public key]

SUPABASE_SERVICE_ROLE_KEY=
[Supabase → Settings → API → service_role key]

DATABASE_URL=
[Supabase → Settings → Database → Connection String → URI]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2) NEXTAUTH (opcional / legado — só se usares)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

NEXTAUTH_SECRET=
[Gerar: node scripts/generate-nextauth-secret.js ou openssl rand -base64 32]

3) CRON (obrigatório para crons protegidos)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

CRON_SECRET=
[Segredo forte; mesmo valor para lesson-reminders, payment-suspension, generate-monthly-payments]
[Vercel Cron envia x-vercel-cron; chamadas manuais usam Authorization: Bearer <CRON_SECRET>]
[Ver DOCS/PAGAMENTOS_MENSALIDADES_CRON.md]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4) STRIPE (Pagamentos)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=
STRIPE_SECRET_KEY=
[OBRIGATÓRIO: nome exacto STRIPE_SECRET_KEY — a app NÃO lê STRIPE_API_KEY nem STRIPE_PUBLIC_KEY como chave secreta]

STRIPE_WEBHOOK_SECRET=
[Stripe → Developers → Webhooks → Add endpoint]
[URL: https://teu-dominio.vercel.app/api/stripe/webhook]
[Eventos conforme app (ex.: invoice.paid, checkout)]
[Começa com: whsec_...]

[URL do GLB base; por defeito a app usa /models/human-base.glb]

NEXT_PUBLIC_HUMANOID_BODY_HINT=female
ou male — só relevante se o GLB tiver **dois** rigs (ex.: pack M+F) e não houver humanoid3dBodyVariant na ficha.
Valores aceites: female, f, male, m (case-insensitive).
